# 自动压缩与会话记忆

2026-10-29。此功能替代原先「最多最近 10 轮、48,000 字节后丢弃旧轮次」的策略。

## 开源参考与取舍

- [LangGraph：Summarize messages](https://docs.langchain.com/oss/python/langgraph/add-memory#summarize-messages) 将摘要作为会话状态，结合已有摘要和新增历史持续更新。本项目采用滚动摘要、按会话持久化和渐进式检查点。
- [Pydantic AI：历史处理器与压缩](https://pydantic.dev/docs/ai/core-concepts/message-history/#summarize-old-messages) 将摘要作为用户层级的历史资料传给模型，并说明应保持完整交互边界。本项目也保留完整问答边界，将摘要与系统指令分离。
- 两者都提供了复杂 Agent 框架。本项目保留现有 Rust/Tauri 和 DeepSeek 官网接口，仅借鉴上下文管理方法，没有引入 Python 服务、框架运行时、向量数据库或额外模型供应商。

## 用户可见行为

1. 小规模会话保留所有完整问答，不再按 10 轮截断。停止、失败或上次退出中断的回答仍不进入模型上下文。
2. 提问时先检查工作容量；接近阈值时显示「正在整理会话记忆…」，先生成摘要，再继续流式回答当前问题。当前问题不参与压缩、不被截断。
3. 聊天顶部显示「会话记忆 · 已整理 N 轮历史」，展开可查看摘要。目标、事实/偏好、决定、约束和待办是摘要的重点。
4. 摘要与当前会话一起保存在本机，重启后复用。新对话不继承其他会话的摘要，删除会话会一起删除摘要。完整聊天原文不删除，仍可从历史中查看。
5. 压缩和回答共享停止按钮。压缩失败不会直接丢弃旧历史继续回答；显示错误并允许重试。已经成功生成的完整批次摘要保留，重试可以从检查点继续。

## 容量策略

这是一套**应用工作预算**，不是 DeepSeek 官网最大上下文窗口的声明，也不是精确 tokenizer 计数。按 UTF-8 字节数加每条消息 16 的开销估算，通常比普通文本 token 数更保守。

- 总工作预算：128,000 估算单位。
- 预留当前系统提示词的完整字节数、当前思考档位的输出上限，以及 2,048 余量。
- 待发送的「摘要 + 未覆盖原文 + 当前问题」超过剩余预算的 80% 时触发压缩。
- 优先保留能容纳于约一半预算内的近期完整问答；其他较早问答被分批摘要。近期原文保留多少轮由实际大小决定，没有固定轮数。
- 摘要最多 8,000 UTF-8 字节；摘要调用固定使用当前 `deepseek-flash`、关闭思考、输出预算 2,800 tokens。压缩使用的指令与用户手写 `system-prompt.txt` 分离。
- 旧历史按最多约 24,000 字节一批分组。单个超大轮次会在 UTF-8 字符边界分片处理，所有分片成功后才推进该轮的检查点。不会把一整份巨大旧会话直接提交给压缩请求。
- 压缩最长 10 分钟，单次摘要请求最长 120 秒；超时可重试。回答阶段仍使用原有思考档位和超时。

较长的旧会话首次迁移可能需要多次摘要 API 调用，会增加等待和费用。短会话不调用摘要模型。完整聊天的本机存档容量限制仍独立存在。

## 一致性与权限边界

摘要记录 `version`、`summary`、`coveredMessages`、`digest` 和 `updatedAt`。SHA-256 覆盖所代表的原始消息角色与正文，重试或恢复时核对内容；不匹配则从完整历史重新构建，避免沿用失效摘要。旧存档没有 memory 字段也可正常打开。

每次只提交连续、完整的已完成问答批次。部分压缩失败不推进未完成批次的范围。前端按请求 ID 忽略旧事件，并按会话 ID 保存记忆，防止串话；记忆跟随原有有序、原子文件保存队列落盘。

最终输入顺序：`用户的 system 文件 → 带明确边界的历史摘要（user 资料）及确认 → 近期完整原文 → 当前 user 问题`。摘要不是 system 消息，不得覆盖用户的系统提示词。摘要内容是模型生成的有损资料，不能保证每个细节永远准确保留；关键长期指令仍适合写在独立系统提示词文件里。这一版的 memory 是**会话内持久记忆**，不自动在不同会话之间传播个人信息。

## 验证

- 21 项前端测试：包含摘要状态、查看、保存/重载、会话隔离、压缩取消、失败重试、旧请求摘要被忽略；另验证超过 10 轮与大历史未在前端截断。
- 16 项 Rust 离线测试通过：涵盖小会话不触发摘要、多批次压缩、摘要复用、原文改变导致校验失效、失败后保留检查点、超大轮次分片、取消不提交未完成摘要，以及历史文件 round-trip 和既有功能；Clippy 零警告检查通过。
- `live_context_memory` 使用较小测试预算触发真实压缩；两次官网 API 调用验证合成历史的项目代号和约束进入摘要，并在后续问答中正确取回代号。未使用用户聊天资料。脱敏结果见 `artifacts/local/context-memory-live.json`。
- 默认测试跳过真实 API 测试，手动执行会计费：

```powershell
cargo test --manifest-path src-tauri/Cargo.toml live_context_memory -- --ignored --nocapture
```
