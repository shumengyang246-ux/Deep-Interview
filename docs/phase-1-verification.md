## 原生窗口与本机捕获

原生 debug 构建通过（Tauri 2.12.5），得到可独立启动的 `src-tauri/target/debug/deep-interview.exe`。

`npm run verify:capture` 最终通过，证据见 `artifacts/local/capture-report.json`：

| 检查 | 实测结果 |
| --- | --- |
| 系统保护标志回读 | 17，即 `0x11 / WDA_EXCLUDEFROMCAPTURE` |
| 不启用保护时的测试色块覆盖率 | 100% |
| 启用保护后的测试色块覆盖率 | 0% |
| 启用保护后的原背景覆盖率 | 100%，没有黑块 |
| 原生置顶开 / 关 | 通过 |
| 原生隐藏 / 恢复 | 通过 |
| 紧凑 / 展开尺寸恢复 | 通过，200% 缩放下物理高度 128 → 1340 |
| 全局快捷键注册 | 成功 |

这些窗口检查直接调用与 UI 相同的 Rust 命令，再回读窗口状态。它们不冒充鼠标点击或物理按键测试。全局快捷键实际按键、标题栏拖动和托盘点击仍应由用户进行一次交互验收。

补充边界：表中「隐藏 / 恢复」检查的是可见性，不代表恢复后的捕获像素也通过。后续开关试验中曾观察到“开启保护 → 隐藏 → 恢复”在本机 GDI 捕获留下黑色占位、没有捕获到聊天色块。开关方案现已按用户要求撤回，恢复启动及唤回时默认开启；此次回退不等于证明上述黑块现象已经解决。该试验报告另存为 `artifacts/local/capture-toggle-investigation-report.json`，不能与当前基础对照测试混同。

真实窗口的无障碍树显示「捕获排除已启用」。桌面工具截图观察到该窗口位置的底层画面，而不是助手内容；没有将包含底层桌面的截图保存为项目证据。桌面点击自动化两次遇到 `window bounds changed`，随后激活时返回 `user input was detected`，因此未继续争抢输入，而由上述原生命令对照验证窗口功能。

测试最初使用 RGB ±5 的色值容差，实际捕获的品红色为 `(192,57,141)`，与 CSS `(207,57,139)` 有偏差，导致假阴性。容差调整为 ±24 后，未保护色块与受保护背景均正确识别；两种测试色在绿色通道上相距超过 150，阈值仍能明确区分色块、背景和黑块。

机器生成证据保存在 `artifacts/local/`，默认不纳入 Git；可重新运行验证脚本生成。
